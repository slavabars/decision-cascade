# Политика безопасности

## Поддерживаемые версии

Проект в стадии **beta**. Исправления безопасности выходят в последней версии
ветки `main` и в последнем GitHub Release.

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Используйте приватный канал:

- GitHub Security Advisories — вкладка **Security → Report a vulnerability**
  репозитория `slavabars/decision-cascade`;
- либо письмо на `slavabars@users.noreply.github.com` с меткой `[security]`.

В сообщении укажите: версию/коммит, окружение, шаги воспроизведения, влияние и,
если есть, черновик исправления. Ожидайте ответ в течение ~7 дней.

## Модель угроз и границы

Проект рассчитан на **локальный self-hosted** запуск под вашим контролем. Он не
предоставляет ни облачного сервиса, ни общей инфраструктуры, поэтому основной
периметр — это ваша машина и сеть, в которой развёрнут сервер.

### Сервер не аутентифицирует запросы

`api.server.main:app` намеренно не содержит встроенной аутентификации, CORS и
rate-limiting. Это значит, что **публиковать порт напрямую в интернет нельзя**.

Рекомендации при развёртывании:

- слушайте только `127.0.0.1` и проксируйте через reverse-proxy (nginx/traefik)
  с TLS, аутентификацией и лимитами;
- либо добавляйте проверку токена на уровне шлюза/прокси;
- держите сервер в доверенном периметре.

### Загрузка моделей и медиа

- Веса скачиваются с Hugging Face по `DECISION_MODEL_ID` и родственным
  переменным; используйте доверенные репозитории и, при необходимости, пинните
  ревизии.
- Медиа-путь (CLIP) ограничен allowlist-ом поддерживаемых модальностей и схем
  (см. `src/backends/base.py`): неподдерживаемые входы отклоняются типизированной
  ошибкой.

### Секреты

Реальные секреты в репозиторий не коммитятся. Токены (`HF_TOKEN`, `GH_TOKEN` и
т.п.) передавайте через переменные окружения, а не через файлы в git.
