# Option-scoring голова: набор вариантов без переобучения

Обычная `ChoiceHead` — это `Linear(dim, k)`: у каждого варианта **свой** вес, а
число выходов зашито на момент обучения. Добавить, убрать или переименовать
вариант можно только переобучением всей головы.

Option-scoring голова оценивает каждый вариант **общим** скорером по его
текстовому эмбеддингу, поэтому число её обучаемых параметров не зависит от числа
вариантов, а набор вариантов можно подменить на инференсе теми же весами.

## Как это устроено

Оценка варианта — **билинейная** форма (`.venv`/`src/decision_head/heads.py`):

```
logit_i = < f(h) , g(e_i) > / sqrt(dim)
```

где `h` — признаки состояния, `e_i` — эмбеддинг варианта, `f`/`g` — общие
линейные проекции (`state_proj`, `option_proj`).

- Эмбеддинги вариантов строятся из энкодера (`build_option_prompt`: только текст
  вопроса и варианта, **без состояния**) и хранятся как **неперсистентный буфер**:
  в чекпоинт они не пишутся, а пересчитываются из энкодера. Поэтому обученные
  `f`/`g` переносятся на произвольный набор вариантов — в том числе другой
  ширины.
- Билинейность принципиальна. Аддитивная форма `linear([f(h) ; g(e_i)])` вырождена:
  вклад состояния `f(h)` одинаков для всех вариантов, и голова всегда выбирает
  один и тот же вариант (точность уровня случайной). Это проверяется регрессионным
  тестом `test_option_scoring_choice_depends_on_state`.

Режим переключается переменной `DECISION_CHOICE_HEAD` (`linear` по умолчанию,
`option_scoring` — opt-in). Совместимость сохранена: ключ `choice_head` в
чекпоинте необязателен (старые файлы читаются как `linear`), а сервис игнорирует
чекпоинт, если режим не совпал.

## Как измерить

```bash
# офлайн, без модели
.venv/bin/python -m eval.option_transfer.run --encoder hash --dim 64 --seeds 0 1 2

# с семантическим энкодером
.venv/bin/python -m eval.option_transfer.run \
  --encoder openai-community/gpt2 --dim 768 --seeds 0 1 2
```

Задача синтетическая: состояние — фраза о еде, полярность задана словами из
словаря, **не пересекающегося с вариантами** (иначе ответ угадывался бы по
совпадению слова). Голова обучается только на трёх вариантах
(`poor/neutral/good`), затем ей **подменяют** набор вариантов теми же весами.
Сравнение — с головой, обученной на этом наборе с нуля (верхняя граница без
переноса). Метрики усредняются по seed'ам: перенос чувствителен к инициализации и
геометрии энкодера, одиночный прогон вводил бы в заблуждение.

## Референсные числа

3 seed'а, mean±std; chance указан рядом.

| Энкодер | Настройка | option-scoring | linear (с нуля) | chance |
| --- | --- | --- | --- | --- |
| gpt2, dim 768 | обучение (in-dist) | 1.000±0.000 | 1.000±0.000 | 0.333 |
| gpt2, dim 768 | zero-shot, 2 невиданных варианта | **1.000±0.000** | 1.000 (переобучение) | 0.500 |
| gpt2, dim 768 | те же + знакомые варианты рядом | **0.000±0.000** | — | 0.200 |
| gpt2, dim 768 | 2 совершенно новых слова | **0.312±0.027** | 1.000 (переобучение) | 0.500 |
| hash, dim 64 | обучение (in-dist) | 1.000±0.000 | 1.000±0.000 | 0.333 |
| hash, dim 64 | zero-shot, 2 невиданных варианта | 0.500±0.000 | 1.000 (переобучение) | 0.500 |
| hash, dim 64 | те же + знакомые варианты рядом | 0.000±0.000 | — | 0.200 |
| hash, dim 64 | 2 совершенно новых слова | 0.525±0.035 | 1.000 (переобучение) | 0.500 |

## Честный вывод

**Перенос работает только когда новые варианты семантически близки к обученным.**
На gpt2 голова, обученная на `poor/neutral/good`, без переобучения ранжирует
невиданные `dreadful/excellent` идеально (1.000 — на уровне головы, обученной с
нуля). Это подтверждается контрольным прогоном: если убрать список вариантов из
промпта состояния, результат не меняется (утечки нет).

Но граница узкая:

- **Знакомые варианты «перебивают» новые.** Если рядом с невиданными оставить
  обученные варианты (набор из всех пяти), голова никогда не выбирает невиданные
  (0.000). На практике это значит, что добавленный вариант соревнуется с
  обученными и обычно проигрывает.
- **Совершенно новые слова не переносятся.** На не связанных с обучением словах
  (`terrible/flawless`) точность 0.31 — **ниже** chance 0.5 (систематическая
  инверсия). Геометрия эмбеддингов вариантов семантически произвольна
  (центрированные косинусы: `poor`↔`neutral` = −0.88, `dreadful`↔`excellent` =
  −0.07), поэтому «семантического» механизма, который обобщал бы на любые слова,
  нет.
- **На hash-энкодере переноса нет вообще** (везде chance): bag-of-hashed-tokens не
  несёт семантики, и это ожидаемо.

Что это значит для практики:

- **Не обещаем «любой новый набор вариантов бесплатно».** Работает подмена на
  близкие варианты; далёкие требуют переобучения.
- **Ценность — в архитектуре и интерфейсе**: один общий скорер вместо `k` весов,
  число параметров не зависит от числа вариантов, и подмена набора вариантов
  технически возможна без изменения весов (для `linear` — нет: её ширина
  фиксирована на обучении).
- Режим по умолчанию — `linear`; option-scoring включается явно
  (`DECISION_CHOICE_HEAD=option_scoring` или `--choice-head option_scoring`).
- Заметка в `docs/risk-aware-cascade.md` предполагала, что option-scoring голова
  может дать риск-модели признак *сложности варианта*. Замер сделан: это средняя
  попарная косинусная близость направлений вариантов
  (`eval/risk/features.py`, вариант `+option_similarity`). Как признак риска он
  **не окупается**: +0.3 п.п. AURC на gpt2/RouterBench и ноль на остальных
  наборах, а стоит поля в `DecisionResult` и изменения API. Поэтому в
  production он не подключён. Выигрыш риск-модели дали признаки, выводимые из
  самого решения (`n_classes`, `noul_logit`, `log_odds_gap`) — см.
  `docs/risk-aware-cascade.md`.
