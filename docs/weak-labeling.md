# Слабая разметка: пак из ответов сильной модели

Разметка руками — узкое место: чтобы обучить головы под свой домен, нужны
тысячи пар «состояние → ответ на каждый вопрос». Слабая разметка заменяет
ручную работу прогоном **учителя** (сильной модели по протоколу SystemOne) по
неразмеченным текстам: ответы учителя становятся метками, а локальные головы
учатся их воспроизводить. Это дистилляция поведения учителя в дешёвый движок,
а не «магия бесплатной разметки».

```text
неразмеченные тексты ──► учитель (SystemOne) ──► JSONL с метками ──► train_heads ──► пак
```

## 1. Что получится и чего не получится

Получится:

- обучить головы под **свой** набор вопросов без ручной разметки;
- перенести поведение сильной модели в локальный инференс (CPU, без сети);
- быстро собрать baseline, чтобы понять, стоит ли вообще размечать руками.

Не получится:

- **превзойти учителя** на этом домене: метки — его ответы, ошибки наследуются;
- **измерить качество по меткам учителя**: это согласие с собой, а не точность.
  Проверка — только на настоящей разметке (`eval.report.run` или свой test);
- **откалибровать вероятности**: головы учатся на жёстких метках, поэтому
  калибровку (`calibrate_temperature`, RLCD) всё равно надо делать на реальных
  исходах.

Правило: слабая разметка годится для **покрытия** домена, а не для финального
числа в отчёте.

## 2. Вход

JSONL, по строке на состояние:

```jsonl
{"id": "t-1", "state": "Stripe webhook падает третий день, клиент теряет выручку"}
{"id": "t-2", "state": "Не приходит письмо со сбросом пароля"}
```

Подойдёт и обычный текст — по строке на состояние, и JSONL с полем `text`.
Пустые строки пропускаются; объект без непустого `state`/`text` — ошибка.

## 3. Учитель

Любой сервис, совместимый с `POST /v1/systemone` (Clef/Clef-Flash, Perplexity
Decider, vLLM/SGLang, собственный инстанс decision-cascade с обученным паком).
Учитель должен уметь ответить на **все** вопросы набора; иначе разметка падает
с перечнем пропущенных вопросов, а не пишет молча неполный датасет.

```bash
export DECISION_TEACHER_URL=https://teacher.example/v1
export DECISION_TEACHER_MODEL=clef
```

Бюджет и повторы — как у обычного внешнего бэкенда: `--teacher-timeout`
(по умолчанию 60 с) и `--teacher-retries` (1). Ошибка учителя не превращается в
метку: строка не пропускается молча.

## 4. Разметка

```bash
.venv/bin/python -m training.labeling.run \
  --input data/unlabeled.jsonl \
  --out data/weak/support.jsonl \
  --specs support \
  --teacher-url "$DECISION_TEACHER_URL" \
  --teacher-model "$DECISION_TEACHER_MODEL" \
  --min-confidence 0.6
```

| Флаг | Назначение |
| --- | --- |
| `--input` | JSONL/TXT с состояниями |
| `--out` | JSONL с метками (формат `eval.datasets`) |
| `--specs` | `support`, `public` или `routerbench` — тот же набор, что у `train_heads` |
| `--limit` | взять первые N строк (черновой прогон) |
| `--min-confidence` | выбросить строку, если учитель хоть по одному вопросу уверен меньше порога |
| `--report` | путь к статистике (по умолчанию `<out>.report.json`) |

Метки приводятся к формату обучения:

| Тип вопроса | Метка |
| --- | --- |
| `noul` | `0`/`1` по порогу `noul >= 0.5` |
| `choice` | строка-вариант; вариант вне `options` — ошибка |
| `score` | индекс самого вероятного уровня (без `probabilities` — округление `score`) |

Рядом с датасетом пишется отчёт: сколько строк оставлено/выброшено, средняя
уверенность учителя по вопросам, распределение меток и спецификации вопросов.
По нему видно, где учитель «плывёт»: перекос в один класс или низкая
уверенность — повод сузить домен или поднять порог.

## 5. Обучение и проверка

```bash
# головы на слабых метках
.venv/bin/python -m training.recipe.train_heads \
  --dataset data/weak/support.jsonl \
  --specs support \
  --out-dir checkpoints/weak-support \
  --encoder openai-community/gpt2 --dim 768 --train-steps 300 --device cuda

# честная проверка — на настоящей разметке, не на метках учителя
DECISION_MAX_LENGTH=256 .venv/bin/python -m eval.report.run \
  --specs support --encoder openai-community/gpt2 --dim 768 \
  --train-steps 0 --device cuda --out-dir data/report_weak_support
```

`train_heads` режет датасет на train/val/test по `--seed`; для слабой разметки
полезно держать отдельный **реальный** test-сплит и сверять с ним, а не с
`metrics.test` из метаданных, который посчитан на метках учителя.

## 6. Гигиена

- **Домен.** Чем уже домен, тем меньше ошибок учителя наследуется. Смесь
  поддержки и новостей даст голову, которая не умеет ни то, ни другое.
- **Порог уверенности.** Начните с `--min-confidence 0.6`: выброшенные строки
  дешевле выученных ошибок. Сравните отчёт при 0.0 и 0.6.
- **Баланс классов.** Смотрите `label_distribution`: если учитель отвечает одним
  вариантом на 95% строк, голова выучит константу. Доберите состояния, где
  классы различаются.
- **Утечка.** Не размечайте учителем test-сплит, на котором потом «проверяете»
  голову: получите согласие с учителем, а не качество.
- **Версия учителя.** Зафиксируйте `--teacher-model` и дату прогона в отчёте:
  смена учителя меняет датасет.

## 7. Тесты

`tests/test_labeling.py` проверяет без сети:

- приведение меток всех трёх типов и порог `noul`;
- ошибку на вариант вне `options` и на пропущенный вопрос;
- фильтр `--min-confidence`;
- чтение JSONL/текста и запись датасета, который принимает `train_heads`;
- CLI с подменённым учителем (реальный HTTP не нужен).
