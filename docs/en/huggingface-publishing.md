# Publishing packs to Hugging Face (maintainer)

[Русский](../huggingface-publishing.md) · **English**

This page is for whoever releases packs. Downloading and running them is covered in [`huggingface.md`](huggingface.md).

Repository: `slavabars/decision-cascade-packs` (public model repo). Revisions are HF tags (`v1.5.0`); an existing revision is never overwritten.

## Layout and manifest

```text
README.md          # card, generated by publish_hf.py
manifest.json      # schema_version, library_version, git_commit, generated_at, packs[]
packs/<name>/
  heads.pt         # head weights + question schemas + temperatures
  metadata.json    # encoder, dim, question signature, train/val/test metrics
  temperature.json # calibration report
```

For every pack, `manifest.json` keeps `name`, `encoder`, `feature_dim`, `questions_signature`, `questions`, `dataset`, `dataset_source`, `dataset_license`, `splits`, `metrics.test` and `files` with `sha256` and `bytes`. Datasets (`dataset.jsonl`) are not published: they are reproduced from public datasets, while metadata keeps the hash and split sizes.

## Publisher

`training/recipe/publish_hf.py` (shipped in the wheel):

```bash
# offline: schema, hashes, licenses, staging
.venv/bin/python -m training.recipe.publish_hf --check --library-version v1.5.0
.venv/bin/python -m training.recipe.publish_hf --dry-run --out dist/hf

# publish and verify
.venv/bin/python -m training.recipe.publish_hf --publish \
  --repo slavabars/decision-cascade-packs --revision v1.5.0
.venv/bin/python -m training.recipe.publish_hf --verify \
  --repo slavabars/decision-cascade-packs --revision v1.5.0
```

- `--packs` — pack directory (default `checkpoints/packs`);
- `--exclude` — packs by directory name; default `chess`, `maze`, `ru-rubert-tiny2`;
- `--library-version` — which release the packs belong to (in CI, the weight archive tag);
- `--commit` — git commit the packs were built from, if known;
- `--from-stage` — publish an already built staging directory (CI does this);
- `--check`, `--dry-run`, `--from-stage`, `--verify` never write to the Hub without `--publish`.

Rules:

- authentication is `HF_TOKEN` or a local `hf auth login` (CLI in `huggingface_hub` 2.x; `huggingface_hub.commands` no longer exists). The token is never printed or committed; revoke it if it leaks;
- an existing tag is not overwritten: `publish` compares sha256 and asks for a new revision on mismatch;
- after upload `publish` runs `--verify` itself (with retries for tag propagation).

## CI

`.github/workflows/publish-hf.yml` is `workflow_dispatch` only: packs are not in git, the weight archive comes from a GitHub Release.

- inputs: `packs_release` (default `v1.5.0`), `revision`, `dry_run` (default `true`);
- the `check` job always downloads `*-weights.tar.gz`, builds staging and uploads the `hf-staging` artifact;
- the `publish` job runs when `vars.HF_PUBLISH_ENABLED == 'true'` and `secrets.HF_TOKEN` is set; it publishes from the artifact and runs a smoke test;
- smoke downloads `public-gpt2` via `snapshot_download`, starts `DecisionService` with `DECISION_MODEL_ID=openai-community/gpt2`, and checks `is_trained` plus one answer.

Repository setup:

```bash
gh variable set HF_PUBLISH_ENABLED --body true -R slavabars/decision-cascade
gh secret set HF_TOKEN -R slavabars/decision-cascade < ~/.cache/huggingface/token
```

## Checklist for a new pack or revision

1. The pack is trained and calibrated; `metadata.json` has encoder, dim, signature and metrics.
2. `publish_hf.py --check` passes; dataset license warnings are reviewed.
3. `--dry-run` builds staging, and the pack from staging loads as `DECISION_CHECKPOINT_DIR`.
4. A new revision gets a new tag; the old one is left alone.
5. After publishing, `--verify` and smoke are green.
6. The card and `docs/huggingface.md` have not drifted in numbers (card metrics are generated from the manifest).

## Common failures

| Symptom | Cause and fix |
| --- | --- |
| `already published and matches` | Not an error: tag and files match, nothing was overwritten |
| `published packs differ from the local build` | Files changed under the same tag: bump `--revision` |
| `not authenticated` | No `HF_TOKEN` and no local login: run `hf auth login` |
| `unsafe pack name in manifest` | A manifest path contains `/`, `\` or `..`; publishing is rejected |
| `sha256 mismatch` | Broken cache or archive: re-download; `publish --verify` names the file |
| `trained: false` for a user | Questions, dimension or encoder do not match; the service checks signature, dim and `encoder` |

Tests: `tests/test_publish_hf.py`, `tests/test_packs_hub.py`, `tests/test_multidomain.py`. The user contract is [`huggingface.md`](huggingface.md).
