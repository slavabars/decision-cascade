# Conformal-каскад: гарантия доли ошибок

**Русский** · [English](en/conformal.md)

Порог уверенности и бюджет ошибок задают **желание**: «эскалируем всё ниже 0.6» или «хотим не больше 5% ошибок локально». Но порог подобран на конечной выборке, и на новых данных доля ошибок гуляет — особенно когда калибровка короткая. Conformal-каскад превращает желание в **обещание с вероятностью**: по отложенной калибровке выбирается порог на `P(ошибка)`, для которого верхняя граница доли ошибок среди принятых решений не превышает `alpha`, и это гарантируется без предположений о модели — только об обмениваемости калибровки и новых данных.

```text
P(доля ошибок среди локально принятых ≤ alpha) ≥ 1 − delta
```

Гарантия даётся **по каждому вопросу одновременно**: уровень `delta` делится между вопросами по Бонферрони. Это важно, потому что решения разных вопросов на одном состоянии коррелированы, и складывать их в одну независимую выборку нельзя.

## Как считается

1. Валидация делится на две половины: на первой обучается оценщик `P(ошибка)` (та же логистическая регрессия, что у risk-aware каскада), на второй строится сертификат.
2. Решения сортируются по `P(ошибка)`. Для каждого кандидата-порога считаются принятые решения, число ошибок и **точная верхняя граница Клоппера–Пирсона** с уровнем `1 − delta / Q`, где `Q` — число вопросов.
3. Берётся максимально широкий порог, при котором граница укладывается в `alpha` у **всех** вопросов и покрытие не ниже `min_coverage`. Если такого нет, сертификат честно отдаёт покрытие 0: лучше не принять ничего, чем пообещать больше, чем позволяют данные.

Граница Клоппера–Пирсона не «оптимистична»: при нуле ошибок она равна `1 − delta ** (1 / n)`, поэтому десяток идеальных примеров ничего не доказывает. Чтобы сертифицировать `alpha = 0.05` при `delta = 0.05` без единой ошибки, нужно около 59 примеров, а при делении `delta` на три вопроса — около 67 на каждый вопрос.

## Команды

Сертификат считается офлайн; сервер только читает готовый файл.

```bash
# public / gpt2, мягкая гарантия: alpha=0.1, delta=0.1
python -m eval.conformal.run --specs public --encoder openai-community/gpt2 \
    --dim 768 --train-steps 300 --limit 16000 \
    --alpha 0.1 --delta 0.1 --min-coverage 0.5 \
    --out-dir data/conformal_public

# public / gpt2, строгая гарантия: alpha=0.05
python -m eval.conformal.run --specs public --encoder openai-community/gpt2 \
    --dim 768 --train-steps 300 --limit 16000 \
    --alpha 0.05 --delta 0.1 --min-coverage 0.0 \
    --out-dir data/conformal_public_strict
```

CLI пишет `conformal.json` (его читает прод) и `metrics.json` (все числа и срез гейта). Дефолты: `alpha=0.05`, `delta=0.1`, `min_coverage=0.3`. `delta=0.1` выбран как практичный: при делении на вопросы `0.05` требует слишком много калибровочных строк на каждый вопрос.

Включение в сервисе:

```bash
DECISION_BACKEND=cascade \
DECISION_CASCADE_POLICY=conformal \
DECISION_CONFORMAL_PATH=data/conformal_public/conformal.json \
DECISION_RISK_MODEL_PATH=checkpoints/risk.json \
DECISION_CASCADE_FALLBACK_URL=http://127.0.0.1:30000 \
  uvicorn api.server.main:app --port 8000
```

Оценщик `P(ошибка)` можно обучить отдельно (`python -m eval.risk.run`) или взять из прогона `eval.conformal.run` — там он уже подогнан на первой половине валидации. Причина эскалации в `usage` — `"conformal"`; при отклонённом сертификате — `"conformal_gate"`.

## Реальные числа

Публичный набор (AG News-вопросы `topic`, `business`, `tech_level`), gpt2, `limit 16000`: train 14400, val 1600 (800 на риск-модель + 800 на калибровку), test 4000. В калибровке 2400 решений (по три вопроса на пример).

| Режим | `alpha` | Калибровка: покрытие | риск | верхняя граница | Тест: покрытие | риск | confidence@покрытие | Гейт |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| мягкий | 0.10 | 0.915 | 0.0711 | 0.0999 | 0.918 | 0.0785 | 0.0796 | принят |
| строгий | 0.05 | 0.547 | 0.0175 | 0.0482 | 0.534 | 0.0226 | 0.0413 | принят |

В строгом режиме conformal-порог при том же покрытии почти вдвое точнее ранжирования по уверенности (риск 0.0226 против 0.0413), а обещанные 5% на тесте выдержаны. В мягком режиме покрытие 92% и риск 7.9% — это уже не «страховка», а способ не платить за внешнюю модель на большинстве решений.

RouterBench (`--specs routerbench --limit 8000`, gpt2, `alpha=0.05`, `delta=0.1`, `min_coverage=0.3`) даёт **покрытие 0**: на трёх вопросах с локальной точностью 0.553 данных не хватает, чтобы честно пообещать 5% ошибок хотя бы на 30% решений. Сертификат отказывает, гейт отклонён, каскад фолбэчит на `DECISION_CASCADE_THRESHOLD` с `reason = "conformal_gate"`. Это не сбой, а ожидаемое поведение: на слабом домене честная гарантия просто не находится.

## Гейт «не навреди»

Сертификат несёт вердикт, измеренный на **отложенном тесте**, а не на калибровке:

- покрытие не ниже `min_coverage`;
- риск не выше `alpha` с допуском `tol = 0.01`;
- риск не хуже ранжирования по уверенности при том же покрытии.

Если вердикт отрицательный, conformal-порог не применяется: эскалация идёт по `DECISION_CASCADE_THRESHOLD`, `usage.reason = "conformal_gate"`, а причина видна в `GET /info → engine.conformal_gate_worse`. Ослабить гейт переменной окружения нельзя — только пересчитать сертификат на данных, где он проходит.

## Ограничения

- **Обмениваемость.** Гарантия держится, пока новые данные похожи на калибровку. Смена домена, разметки или модели голов требует нового сертификата; старый файл продолжит работать, но обещание к новым данным не относится.
- **Цена Бонферрони.** Чем больше вопросов, тем меньше `delta` на каждый и тем больше калибровочных строк нужно. На десяти вопросах при `delta=0.1` остаётся `0.01` на вопрос — без тысяч решений покрытие, скорее всего, будет нулевым.
- **Сертификат фиксирован.** Обратную связь conformal-каскад не принимает: «дообучение» порога без пересчёта границы сломало бы обещание. Пересчёт — только офлайн-командой.
- **Короткие вопросы.** Гейт держится на общем риске: на вопросе с сотней решений шум несравним с `alpha`, поэтому по-вопросные числа в `conformal_test.groups` — диагностика, а не отдельная гарантия.
- **Покрытие 0 — валидный ответ.** Если данных не хватает, сертификат отказывает. Это лучше, чем порог, который выглядит рабочим, но ничего не гарантирует.
