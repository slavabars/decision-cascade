# Обратная связь без смещения: исследовательские эскалации и IPS

**Русский** · [English](en/exploration.md)

Benefit-каскад уточняет точность внешней модели `q` по обратной связи. Проблема в том, откуда берётся эта обратная связь: разметку присылают по ответам, которые ушли наружу, а уходят наружу трудные случаи. Если трудность коррелирует с качеством внешней модели, оценка `q` считается по смещённой выборке — и цикл замыкается: заниженная `q` опускает порог, эскалаций становится меньше, выборка становится ещё труднее.

Это не гипотеза о «плохих клиентах»: так устроен любой сбор фидбэка по факту вызова. Ниже — измеренная величина смещения, цена исправления и способ включить его в сервисе.

## Механика

`q` сдвигается байесовски, априорная оценка весит `W = DECISION_CASCADE_FEEDBACK_SHRINKAGE` (50) псевдонаблюдений:

```text
q_new = (q_prior * W + Σ w_i * y_i) / (W + Σ w_i)
```

где `y_i` — был ли ответ внешней модели верным, а `w_i` — вес наблюдения. Эскалация по политике детерминирована, поэтому её вес равен 1: без исследования формула совпадает с прежней. Исследовательская эскалация происходит с вероятностью `epsilon`, и её вес `1 / epsilon` возвращает наблюдению «представительство» похожих решений, которые политика оставила локально. Это inverse probability weighting (IPS), он же off-policy evaluation: оценка сходится к качеству внешней модели на всей популяции, а не на эскалированной подвыборке.

Вес ограничен сверху: `min(1 / epsilon, 20)`. При `epsilon = 0.01` вес был бы 100, и одно наблюдение сдвигало бы `q` на десятки процентов. Потолок смещает оценку только в хвосте распределения весов, зато держит дисперсию под контролем; при `epsilon >= 0.05` ограничение не срабатывает.

Вероятность эскалации пишется в журнал `DECISION_FEEDBACK_PATH` вместе с наблюдением, поэтому после рестарта IPS-суммы восстанавливаются, а не начинаются заново.

## Симуляция

Симуляция изолирует оценщик, а не качество моделей (`python -m eval.feedback.run`). Строки генерируются из двух страт: лёгкие (локальная уверенность 0.65–0.95, точность внешней модели `q_easy`) и трудные (уверенность 0.45–0.64, `q_hard`). Политика видит только уверенность; правильность внешней модели зависит от страты. Полезность считается в единицах «верный ответ = 1» при допущении, что локальная уверенность калибрована: локально — `p`, эскалация — `q` минус цена вызова. `regret` — потеря относительно оракула, который знает качество внешней модели на каждой строке.

Параметры прогона: `q_prior = 0.75`, `W = 50`, `C = 0.05`, `D = 1.0`, 5 seed'ов, 30 волн по 1000 решений. Сценарий `correlated` — трудные для локальной модели случаи трудны и для внешней (`q_easy = 0.95`, `q_hard = 0.60`, доля трудных 0.35, истинная `q = 0.8275`). Сценарий `anti` — внешняя модель сильнее именно на трудных (`q_easy = 0.70`, `q_hard = 0.95`, истинная `q = 0.7875`).

| Сценарий | Оценщик | `epsilon` | `q_hat` | Смещение | Доля эскалаций | Доля вызовов | Regret |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| correlated | naive | 0 | 0.6140 ± 0.0074 | −0.2135 | 0.298 | 0.298 | 0.0676 |
| correlated | naive | 0.05 | 0.6480 ± 0.0110 | −0.1795 | 0.352 | 0.384 | 0.0651 |
| correlated | ips | 0.05 | 0.8272 ± 0.0041 | −0.0003 | 0.671 | 0.687 | 0.0172 |
| anti | naive | 0 | 0.8285 ± 0.0017 | +0.0410 | 0.681 | 0.681 | 0.0251 |
| anti | naive | 0.05 | 0.8265 ± 0.0016 | +0.0390 | 0.677 | 0.693 | 0.0280 |
| anti | ips | 0.05 | 0.7896 ± 0.0042 | +0.0021 | 0.601 | 0.621 | 0.0184 |

Читается так:

- **Без исследования оценка уезжает на 21 п.п.** в сценарии, где трудные случаи трудны и для внешней модели, и на 4 п.п. в обратную сторону, где внешняя сильнее на трудных. Направление зависит от домена, поэтому проверяются оба знака.
- **Случайной подвыборки без весов мало.** При `epsilon = 0.05` и наивном счёте смещение остаётся −18 п.п.: наблюдения добавились, но каждое по-прежнему представляет только себя, а не популяцию.
- **IPS снимает смещение.** С 5% исследовательских вызовов оценка попадает в ±0.005 от истины. Цена — рост доли вызовов с 0.30 до 0.69: исправленная `q` поднимает порог, и политика начинает эскалировать то, что раньше недооценивала. По полезности это выигрыш: regret падает с 0.068 до 0.017, то есть политика отыгрывает почти всю потерю относительно оракула.
- **Обратный сценарий тоже исправляется**: смещение +4.1 п.п. → +0.2 п.п., regret 0.025 → 0.018.

Ограничения замера: страты синтетические, локальная уверенность предполагается калиброванной, цена вызова постоянна. Симуляция отвечает на вопрос «что делает оценщик при известной структуре смещения», а не «насколько хороша внешняя модель на вашем домене». Для второго нужен прогон на своих данных.

## Как включить

```bash
DECISION_BACKEND=cascade \
DECISION_CASCADE_POLICY=benefit \
DECISION_CASCADE_REMOTE_ACCURACY=data/public_laya_accuracy.json \
DECISION_CASCADE_EXPLORE=0.05 \
DECISION_CASCADE_FALLBACK_URL=http://127.0.0.1:30000 \
  uvicorn api.server.main:app --port 8000
```

- `DECISION_CASCADE_EXPLORE` — доля решений, которые политика оставила бы локально, но они всё равно уходят наружу (`0…1`, по умолчанию `0` — поведение не меняется).
- `DECISION_CASCADE_EXPLORE_SEED` — зерно генератора для воспроизводимости (по умолчанию случайное).
- `GET /info → engine`: `explore_rate` — заданная доля, `explore_calls` — сколько исследовательских вызовов сделано в текущем процессе.
- `usage.escalated` включает исследовательские вызовы; `usage.reason` остаётся `"benefit"`.

Начинать стоит с 1–5%: при `epsilon = 0.05` потолок веса не срабатывает, а оценка уже сходится; меньшие значения дешевле, но дисперсия выше, а при `epsilon < 0.05` вес начинает упираться в потолок.

Воспроизвести замер:

```bash
.venv/bin/python -m eval.feedback.run --json data/feedback_sim/report.json
```
